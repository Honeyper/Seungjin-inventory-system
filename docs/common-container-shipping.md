# 공용용기 출고 (DEV)

제품 관리에서 공용용기 여부와 출고 제품명 목록을 등록합니다. PC 출고 완료와 모바일 QR 정상출고에서 실제 제품 지정 창이 열립니다. 출고대기까지는 기존 흐름을 사용하고, 정상출고 완료 전에 반드시 제품을 지정합니다.

- 전체 적용: 선택한 제품을 모든 대상 박스에 지정합니다.
- 혼합 박스: `다른 제품 나누기`로 제품별 수량을 입력합니다. 한 박스 안에서 같은 제품을 중복 지정할 수 없습니다.
- 각 박스의 제품별 합계는 현재 박스 수량과 일치해야 합니다. 부분 출고는 출고할 박스를 선택하는 기존 방식을 사용합니다. 공용용기 박스의 수량 자체를 줄여 출고하는 작업은 잔여 재고 유실을 막기 위해 거절합니다.
- 제품 미지정, 미등록 제품명, 음수·소수 수량, 수량 불일치, 이미 출고된 박스는 서버에서도 거절합니다.
- 이관·반출·재고조정과 일반 제품은 기존 처리 방식을 유지합니다.

## 저장 및 조회

원래 공용용기 `productId`와 관리 ID는 유지합니다. 새 재고 SKU를 만들지 않습니다.

각 박스의 JSON 데이터에 `shippingAllocations: [{ productName, quantity }]`를 저장하고, 완료·취소 기록은 `commonContainerShippingHistory`에 저장합니다. 저장은 기존 `commit_dev_state_mutation`의 버전 검사와 트랜잭션을 따릅니다. 취소하면 현재 배분은 비우며 이전 출고 제품명은 취소 이력에 남습니다. 출고 목록과 상세 출고 이력에 실제 제품별 합계를 표시합니다. 목록의 박스 수·전체 수량은 실제 박스 기준으로 유지합니다.

이 데이터는 Supabase의 박스 JSON과 변경 요청(outbox)에 보존됩니다. 기존 스프레드시트의 전용 제품별 출고 컬럼은 추가하지 않습니다. 과거 출고에 실제 제품명을 추정해 소급 입력하지 않습니다.

## 변경 지점

- `frontend/common-container-shipping.js`, `.css`: PC·모바일 공통 지정 창, 요청 전 준비, 이력 요약
- `frontend/admin.js`, `frontend/mobile/mobile.js`: 출고 요청 연결과 내역 표시
- `supabase/functions/seungjin-dev-gateway/common-container-shipping.js`: 등록 제품명·박스별 합계 검증과 이력 저장
- `state-engine.js`, `index.ts`: 서버 출고 및 조회 연결
- `tests/common-container-shipping.test.mjs`: 혼합 출고, 잔여 재고, 검증 실패, 취소·재출고, 기존 흐름 회귀 검증

DEV 전용 변경입니다. 운영(main)으로 반영하려면 별도 승격이 필요합니다.
