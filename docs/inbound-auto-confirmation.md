# 입고 시 자동 실물 확인

- 새 입고의 완박스·잔량 박스에 입고 날짜/시간을 `lastInventoryCheckedAt`으로 저장합니다. 등록 버튼을 누른 현재 시간이 아니라 실제 입고 시각이 기준입니다.
- 확인 시각이 없는 기존 박스도 조회 시 해당 입고 시각을 최초 확인으로 해석합니다. 기존 DB의 이력을 일괄 덮어쓰지 않습니다. PC의 이전 캐시에도 같은 규칙을 적용하며, 모바일 캐시는 새 버전으로 다시 읽습니다.
- 직접 확인한 박스는 그 기록을 우선합니다. 단순 입고 수정·자리 변경으로 확인 기간을 다시 시작하지 않습니다.
- 매월 30일 00:00(한국 시간)에 모든 대상 박스를 재확인 대상으로 전환합니다. 2월은 28일(윤년 29일)을 적용합니다. 9월 29일 12:00 입고는 9월 30일 00:00부터 미확인이며, 9월 30일 00:00 이후 입고·실물 확인한 박스는 10월 30일까지 확인 완료입니다. 입고일로부터 한 달을 기다리지 않습니다.
- 출고대기·출고완료·보류·폐기 및 수량이 없는 박스는 실물 확인 대상에서 제외합니다. 재고정리 가능 여부와는 별도 규칙입니다.
- 입고 날짜가 없거나 잘못되면 자동 확인을 만들지 않습니다. 미래 입고일은 해당 시각 전까지 확인 완료로 집계하지 않습니다.
- 상세보기의 최종 확인일도 박스의 확인 기록과 입고 기준 시각을 반영합니다. 백업에서 복구한 예전 박스에 최초 확인 값이 없어도 입고 날짜가 있으면 동일하게 계산됩니다.

월간 전환은 조회할 때 확인 시각과 공통 기준일을 비교하여 계산합니다. 별도의 일괄 수정이나 예약 작업 없이 적용되며, 기존 확인 이력·수량·위치는 유지합니다. 자리이동 조사로 명시적으로 미확인 처리한 박스는 자동 입고 확인으로 되돌리지 않습니다. 서버 조회 캐시는 한국 날짜별로 분리하고, 모바일은 날짜가 바뀌면 동일 데이터 버전이어도 최신 상태를 조회합니다.

검증: `tests/inbound-auto-confirmation.test.mjs`, `tests/inventory-confirmation-cycle.test.mjs`. 생성·잔량·공통 기준일·윤년·월간 경계·기존 입고·이전 캐시·직접 확인 우선·단순 수정 보존을 포함합니다.
