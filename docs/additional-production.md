# 추가 생산 박스

입고 행의 관리 메뉴에서 `추가 생산 박스 등록`, 재고 행에서 `추가 생산`을 선택합니다. 추가 박스별 실제 수량, 같은 제품의 사출 재고별 사용량, 생산일·위치·로스를 입력합니다. **사출 사용량 = 추가 박스 수량 합계 + 로스**여야 합니다. 등록 후 추가한 박스 라벨만 열립니다.

- 원래 입고·발주 수량과 기존 박스 ID·수량·출고 이력은 바꾸지 않습니다. 원래 라벨의 `1 / 10 Box`는 유지하고 새 박스에는 고유 ID와 `추가 1 Box`를 부여합니다. 재고 요약은 실제 추가 박스와 사용 후 사출 잔량으로 계산합니다.
- 사출은 같은 제품·다른 입고 건의 사출 재고만 선택할 수 있습니다. 출고대기·보류·폐기·출고완료·소진 재고는 사용할 수 없습니다. 완전히 사용한 박스는 `사용완료`로 기록하며 출고량에 포함하지 않습니다.
- 변경은 기존 버전 비교 RPC에서 박스·재고 요약·사용/로스 이력·시트 outbox와 함께 원자적으로 저장합니다. 읽기는 대상 제품의 재고만 조회합니다. 제품별 누적 외부 입고량과 발주의 입고율은 증가시키지 않습니다.
- 요청 ID와 입력 지문을 대상 재고 이력에 저장합니다. 응답 유실 후 같은 요청은 이미 저장한 결과를 반환하며 시트 작업도 재등록하지 않습니다. 같은 ID로 다른 내용을 보내면 차단합니다. 쓰기는 자동 재시도하지 않습니다.
- 추가 생산·사출 사용 이력이 있는 입고의 수량 구성 변경/삭제는 차단합니다. 위치·비고 수정은 박스와 사용 이력을 보존합니다.
- 야간 엑셀 사본은 인증된 outbox의 확정된 재고·박스 스냅샷을 ID별로 반영합니다. 사출 차감 계산을 재실행하지 않으며, 반복 실행 시 추가 박스가 중복 생성되지 않습니다. 그 외 박스와 수기 컬럼은 보존합니다. `Supabase 원본(JSON)`에 추가 생산·사출 사용 메타데이터도 보존합니다.

검증: `tests/additional-production.test.mjs`, `tests/additional-production-backup.test.mjs`, `node tools/browser-smoke.cjs --additional-production-only`. 브라우저 검사는 실제 서버를 호출하지 않는 격리된 환경에서 저장 응답 유실·같은 요청 재전송, 추가 QR만 열기, 사출 검색, Esc 닫기와 1280/390px 입력창을 확인합니다.
